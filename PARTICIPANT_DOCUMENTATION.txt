Model Details

The model must be made in Python.

Each team submits one Python model file. The platform will import this file in a
local, embedded worker process and will call the function `decide(observation)`
once for each living sphere controlled by the team, on every tick.

Tampering with the client or environment outside of the documented model
interface, modifying platform files, or using undocumented attributes,
functions, bugs, or implementation details is prohibited and may result in
immediate disqualification.

The models may be fine-tuned to take advantage of the physics model and dynamic
constraints of the environment:

- The arena is 200 x 200 units, centred at (0, 0).
- A sphere's maximum horizontal speed is 18 units.
- Hitting an obstacle or raised ramp edge at a speed of 11 or more eliminates
  the sphere. Lower-speed impacts stop or push the sphere away.
- When opposing spheres collide, the slower sphere is eliminated. If their
  speeds are equal, both spheres are eliminated. Teammates bounce off each
  other instead.
- A sphere can jump only while grounded. A jump rises roughly 2 units above its
  current support surface.
- Eliminated spheres respawn at their original spawn position after 3 seconds
  (60 ticks).
- The arena boundary stops horizontal movement; it does not eliminate a sphere.


Interface

The model is run locally by an embedded environment; it is not an external API
or service.

Models must expose a function named `decide` that accepts one parameter:

    def decide(observation):
        return (throttle, turn, jump)

or:

    def decide(observation):
        return (throttle, turn, jump, sonar_message)

The function is expected to respond within 30 ms. If it raises an exception,
fails to load, returns an invalid action, or times out, the platform substitutes
an idle action for that call. A timeout restarts the team worker, so any Python
state held in memory is lost.

The first three return values are required:

    throttle      float from -1.0 to 1.0
                  1.0 accelerates forward; -1.0 accelerates backward.

    turn          float from -1.0 to 1.0
                  Controls the sphere's turn direction.

    jump          boolean
                  Causes a jump if the sphere is grounded.

The optional fourth value is:

    sonar_message Any small, picklable Python value, or None.
                  A non-None value is sent to eligible nearby teammates.

Inputs outside the `[-1.0, 1.0]` range for `throttle` and `turn` are clamped by
the platform. Participants should nevertheless return finite numeric values and
not rely on invalid types or values.


Observation

The `observation` parameter is a dictionary with these keys:

    tick -> int
        Current simulation tick. The simulation runs at 20 ticks per second.

    self -> dict
        State of the sphere currently being controlled. Its keys are:

            id -> int
                Stable global sphere identifier.

            team -> str
                Name of the sphere's team.

            player -> int
                Stable player number within the team.

            x, y, z -> float
                Current world coordinates.

            vx, vy, vz -> float
                Current velocity components.

            speed -> float
                Current horizontal speed.

            yaw -> float
                Direction the sphere faces, in radians. A yaw of 0 faces the
                positive Y direction. Forward is (sin(yaw), cos(yaw)).

            grounded -> boolean
                Whether the sphere can currently jump.

            alive -> boolean
                Whether the sphere is alive. In normal operation `decide` is
                called only for living spheres.

            carrying -> str | None
                The team name of the opponent flag currently carried, or None.

    visible_enemies -> list[dict]
        States of enemies currently visible. Each entry has the same format as
        `self`. Enemies are visible only if they are alive, within 40 units,
        inside the 70-degree forward viewing cone, and not hidden behind
        sufficiently tall terrain.

    own_flag -> dict
        State of this team's flag:

            team -> str
            x, y -> float
            carried_by -> int
                Global id of the carrier, or -1 if the flag is not carried.
            at_home -> boolean

    other_flags -> list[dict]
        The same flag state for every opposing team.

    teammates -> list[dict]
        States of all other living teammates. Teammates are supplied regardless
        of view range. The currently controlled sphere is not included.

    score -> dict[str, int]
        Current score for every team.

    sonar_receive -> list[dict]
        Teammate sonar messages that are audible this tick. Every entry is:

            from_id -> int
            from_player -> int
            value -> any

        `value` is the sonar_message returned by the teammate.

    sonar_recieve -> list[dict]
        Legacy misspelling of `sonar_receive`. Both keys contain the same data.
        Participants should use `sonar_receive` in new models.

    death_messages -> list[dict]
        Recent deaths from the controlled sphere's team. Every entry is:

            player -> int
            team -> str
            tick -> int
            x, y -> float
            reason -> str     # "wall", "player", or "unknown"

        This is a recent-event log, not an unread message queue. Existing
        entries can be received again on later ticks.


Sonar

Returning a non-None `sonar_message` broadcasts that message to living
teammates who are within 10 units and have unobstructed line of sight. Messages
are delivered on the following tick; same-tick replies should not be expected.
Return None as the fourth action value to stop broadcasting.


Game Objective

Each team owns one flag at its home position. To score:

1. Move within 2.5 units of an opponent flag to collect it.
2. Carry the flag within 2.5 units of your own flag's home position.

The own flag does not have to be at home for a score to count. If a flag carrier
is eliminated, the carried flag returns to its home position.


Important Limitations

The model does not receive obstacle polygons, ramp geometry, the map seed,
spawn positions, or locations of unseen enemies. These are intentionally not
part of the model interface. Participants must not access undocumented platform
state to obtain them.

One worker process serves all spheres on a team. Module-level Python variables
are therefore shared by that team's spheres. If state is needed, participants
should store it by sphere `id` or `player`, rather than assuming a single
current agent. Worker restarts clear this state.


Environment Info

The environment used for local development is contained in this repository.
To add a team model:

1. Create a Python model file, for example `teams/my_team/model.py`.
2. Expose the `decide(observation)` function in that file.
3. Add or update the team's entry in `teams.json`, setting `model_path` to the
   model file and providing a team name (and optionally a colour).
4. Run the match with:

       python main.py

   An optional integer seed may be passed as the first argument for repeatable
   map generation:

       python main.py 42

The included `teams/example_team/model.py` is a reference implementation.
